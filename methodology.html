Benchmarks: Methodology

First results are live for one vendor. On 22 Nov 2026 ScrapeTools ran this method on Firecrawl, so far the only API with tested results on this site (results). Every other price, credit system, free-tier term and feature on the site still comes from each vendor's own pages, cited with a link and a verification date. The method was published here in July 2026, and the first run's pages, settings and pass rule were fixed before its first request.

Why publish the method before the results

The strongest complaint against comparison sites in this space is a fair one: the vendors being compared often outrank independent reviewers in search results for their own "best scraping API" round-ups, and a lot of third-party "comparisons" recycle the vendor's own marketing claims without testing anything. The only way an independent site earns credibility here is by running its own tests, publishing the method openly, and being willing to rank a paying affiliate partner below a competitor when the data says so. The plan went up in public months before the first benchmark number did.

What the benchmark measures

  • Success rate. Percentage of requests against a fixed panel of target pages that return a usable, correctly-rendered response (not a block page, CAPTCHA wall, or empty/garbled response). A request counts only if the page's own text, chosen from a normal browser view before the run, comes back and no block-page phrase does.
  • Response time. Median and 95th-percentile latency per successful request, measured end-to-end from our test harness.
  • Cost per 1,000 successful pages. Computed from each vendor's own published pricing at like-for-like settings (same feature flags — e.g., JavaScript rendering on or off — enabled across every vendor tested in that run), not the cheapest possible configuration for one vendor against the most expensive for another.
  • Bot-protected targets, tracked separately from the general success rate since results differ so much by site. The first panel uses two practice pages behind a Cloudflare challenge, which their site lists as challenges for scrapers.

How it stays fair

  • Fixed, disclosed target list. A published set of test URLs spanning static pages, JavaScript-heavy pages, and pages with active anti-bot protection, not a list picked after seeing which vendor does better on it. The November 2026 panel is 19 pages: 13 static, 4 built by JavaScript and 2 bot-protected, each with the text that marks a pass.
  • Polite, fresh requests. One request at a time, at least 8 seconds apart and at least 10 seconds (or the site's robots.txt crawl delay) per site; every page must be allowed by its robots.txt; no retries; cached copies turned off so each request fetches the page.
  • Same settings across vendors in a given run. Every vendor tested with the same feature flags enabled (e.g., JS rendering on, or off) in a given comparison, rather than each vendor's best-case configuration against another's default.
  • Recurring re-runs, not a one-time snapshot. Scraping success rates and anti-bot defenses change on both sides — we intend to re-run the panel on a regular cadence and publish the date of each run, rather than leaving a single result live indefinitely.
  • Affiliate relationships disclosed, not hidden from the ranking. Some vendors tested may be ones we earn an affiliate commission from (see the Affiliate Disclosure) — the fixed target list and published parameters exist specifically so that relationship can't quietly tilt which vendor "wins" a given test.
  • Only publish what we actually ran. No estimated, interpolated, or "typical" numbers standing in for a real test. If a vendor isn't tested yet, its page says so — as this page does now.

First run: Firecrawl, 22 Nov 2026

Firecrawl asked to be added to the site's comparison and offered free credits. The test used its public free plan instead, five rounds over the 19 pages, 95 requests in all, and Firecrawl pays this site nothing. A rule written before the run decided whether it joined the comparison: published monthly credit plans, at least 90% of requests to the static and JavaScript pages passing, no more than 1 credit billed per request, and a run free of harness faults. It met all four, so it now appears on the home page and the cheapest API table, marked Tested. Raw data: CSV and JSON, with timings, status codes and the result of each text check, not the pages' content.

Legal and platform-terms scope

Test targets will be limited to pages and services where automated access is either explicitly permitted or falls within general, publicly-documented technique — no scraping of the org's own confidential client work, and no targets chosen specifically to demonstrate bypassing a site's terms of service. This methodology draws only on public, general-technique knowledge, consistent with the org's standing clean-room policy for all published work.

Status

The harness is built and has run once, on Firecrawl, on 22 Nov 2026. Pages that show Firecrawl's results link to the data. Pages about other vendors keep saying their figures come from vendor pages, because those vendors have not been run yet. Each future run will be dated and published with its raw data, and a re-run replaces nothing silently.

How new pages are produced

Pages added or updated by our automated content system are researched and drafted with AI tools and checked against the vendors' own pages by a separate automated reviewer. They are not individually reviewed by a person.
