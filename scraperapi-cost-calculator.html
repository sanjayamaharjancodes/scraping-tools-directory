How to calculate ScraperAPI credits

The basic formula is successful monthly requests × credits per request = monthly API credits. A normal page request costs 1 credit, but the multiplier rises for harder domains and resource-intensive parameters. That means request count alone does not tell you which plan fits.

ScraperAPI credit multipliers

ScraperAPI documents 1 credit for a normal request, 5 for Amazon or e-commerce, 25 for Google or Bing SERPs, and 30 for LinkedIn. Parameters can also change the cost: rendering, premium routing, screenshots, or bot-bypass requests cost 10 credits; premium plus rendering costs 25; ultra-premium costs 30, or 75 with rendering. Domain-specific logic can override a general estimate, so production budgets should use the vendor's URL Cost API.

What the estimate can and cannot tell you

Use measured credit cost for production budgeting. Some domains have custom costs and can change protection methods. ScraperAPI provides an authenticated URL Cost API and dashboard tool that accept the same parameters as a real request. Put that measured result into “Custom” above when accuracy matters.

The estimator multiplies successful requests by credits per request and selects the first published plan whose included credits cover that total. It does not model failed-request rates, retries, concurrency limits, annual discounts, negotiated pricing, pay-as-you-go overages, or combinations not explicitly priced in the documentation.

Frequently asked questions

How many ScraperAPI credits does one request use?

A standard request uses 1 credit. Amazon requests use 5, Google or Bing SERP requests use 25, and LinkedIn requests use 30. Rendering, premium routing, screenshots, bot bypass, and ultra-premium routing can raise the multiplier.

Do failed requests consume ScraperAPI credits?

ScraperAPI says it charges successful responses with HTTP status 200 or 404. It also charges requests that the customer cancels before the service has had enough time to finish. Other failed requests are not included in this calculator.

Which plan covers one million normal requests per month?

The Startup plan includes 1,000,000 credits, so it covers one million normal 1-credit requests with no headroom. The same plan covers only 100,000 requests when each request costs 10 credits.

Why can the same request volume require different plans?

ScraperAPI uses feature-weighted credits rather than a flat one-request-equals-one-credit model. A workload with rendering or protected domains can therefore consume 5 to 75 times as many credits as the same number of normal requests.
